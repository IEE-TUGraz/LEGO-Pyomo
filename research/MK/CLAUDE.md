# CLAUDE.md

This file provides guidance to Claude Code when working on MK experiment scripts.
See [`README.md`](README.md) for usage, key concepts, and CLI parameter reference.

## Non-obvious patterns

**Solver options flow**: A CLI arg (e.g. `--mip-gap`) sets a key in `cs.dGlobal_Parameters` (e.g. `"pMIPGap"`) inside `execute_case_studies()`. `LEGO._build_model()` reads this and stores it as a plain attribute on the Pyomo model (e.g. `model.pMIPGap`). Both `LEGO.solve_model()` and the direct `execute_case_study()` solve path then read this attribute and apply it to `optimizer.options`. The main loop solve path also logs `"Setting work limit to X"` / `"Setting MIP gap to X"`. The regret and invest-regret paths call `_apply_solver_options(lego, run_params)` immediately after `truth_lego.copy()`, which re-stamps these attributes explicitly from `run_params` (defensive against deepcopy edge-cases) and logs them. When adding a new solver option, update all three places: the main loop, `LEGO.solve_model()`, and `_apply_solver_options()`.

**Resource-management Gurobi options** (`--node-file-start`, `--node-file-dir`, `--threads`): Same plumbing pattern as `--mip-gap` / `--work-limit` (CLI → `cs.dGlobal_Parameters["pNodeFileStart"]` etc. → model attr → `optimizer.options['NodefileStart']` etc.), but deliberately **NOT** added to `identifier_parts` (so filenames don't change between memory configurations), **NOT** in `_SIBLING_COMPARE_KEYS` (so a re-run with different node-file settings is treated as the same sibling and won't trigger an unnecessary re-solve), and **NOT** in `EvaluateMarkov.py` grouping. They are stored in `run_parameters` for traceability only. Validation: `--node-file-dir` without `--node-file-start` raises in *both* `main()` (fail-fast) and `execute_case_studies()` (catches direct callers like `FindInvestmentDataset.py`). When `--node-file-start` is set, `execute_case_studies()` *always* appends `str(os.getpid())` as a subfolder of the base path (user-supplied or the default `./gurobi-nodes/`) — e.g. `E:/tmp/nodes` becomes `E:/tmp/nodes/12345/`. This is unconditional and not user-configurable: it guarantees parallel spawns never collide on a shared dir, even if the user is unaware of the parallelism implications. The post-join value is what's stored in `cs.dGlobal_Parameters["pNodeFileDir"]`, `run_params`, and the SQLite `run_parameters` table. `LEGO.solve_model()` auto-creates the dir (`os.makedirs(..., exist_ok=True)`). Gurobi cleans the dir contents on normal solve exit; stale files only persist after a hard kill; the per-PID subfolder itself persists.

**`--filter-zone` preprocessing order**: Applied first, before `limitK`, in `main()`. It calls `CaseStudy.filter_zone()` (unscaled) and writes the result to a `filterZone{zone}/` subfolder. Exact match on the `z` column of Power_BusInfo — merged-bus zone strings like `"R1_R2"` are not matched by `"R1"` alone. The zone is stored in `run_params` (key `filter_zone`) and included in the sibling-compare key list.

**`--scale-vres`**: Applied in `execute_case_studies()` after loading the CaseStudy (no subfolder). Multiplies `dPower_VRES['MaxProd']` by the factor, covering PV, Wind, and RoR. Stored in `run_params` as `scale_vres` (only if != 1.0) and included in the sibling-compare key list.

**`--scale-invest-cost`**: Applied in `execute_case_studies()` after loading the CaseStudy (no subfolder). Multiplies `InvestCostEUR` in `dPower_ThermalGen`, `dPower_VRES`, and `dPower_Storage` by the factor — covering all generator types that feed `model.pInvestCost`. Line investment (`dPower_Network['pInvestCost']`) is not affected. Stored in `run_params` as `scale_invest_cost` (only if != 1.0) and included in the sibling-compare key list. Encoded in identifier as e.g. `scaleInvestCost0.5`.

**`--shift-tm`**: Applied in `execute_case_studies()` to the base `cs` before any model copies are made (so all four models — Truth, NoEnf, Cyclic, Markov — see the same perturbed Hindex/TM). Calls `CaseStudy.shift_transition_matrix(n, inplace=True)` which cyclically shifts every row of the absolute TM right by `n` positions, normalizes, then resamples a new chronological RP sequence (seeded with `n`) and rebuilds `dPower_Hindex`, `dPower_WeightsRP`, and all three TM attributes. The Truth model (built from Hindex) is therefore also affected. Stored in `run_params` as `shift_tm` and included in the sibling-compare key list. Encoded in identifier as e.g. `shiftTM2`.

**`--perturb-tm`**: Applied in `execute_case_studies()` after `--shift-tm`, to the same base `cs`. Calls `CaseStudy.perturb_transition_matrix(r, inplace=True)` which interpolates each row of the absolute TM between its original distribution and a random draw: `new_prob = (1-r)*orig + r*random`, where the random draw is uniform values normalized to sum to 1. `r=0.0` is a no-op; `r=1.0` fully randomizes. All four models see the same modified Hindex/TM. Stored in `run_params` as `perturb_tm` and included in the sibling-compare key list. Encoded in identifier as e.g. `perturbTM0.5`.

**`--thermal-invest-only`**: Applied in `execute_case_studies()` after loading the CaseStudy (no subfolder). Sets `ExisUnits=1` and `EnableInvest=0` on `dPower_VRES` and `dPower_Storage`, leaving only `dPower_ThermalGen` investable. Stored in `run_params` as `thermal_invest_only` and included in the sibling-compare key list.

**`--merge-generators` preprocessing order**: Applied after `stretch_demand` and before `clusters` in `main()`. It calls `CaseStudy.merge_generators()` (unscaled) and writes the result to a `mergeGenerators/` subfolder. The subfolder is then used as the base for subsequent clustering. The flag is stored in `run_params` (key `merge_generators`) and included in the sibling-compare key list, so smart-skip treats runs with and without merging as distinct.

**`--no-crossover` and `--force-barrier` are coupled**: `main()` raises if exactly one is set. This is intentional — disabling crossover without barrier produces an interior-point solution that is not a vertex; the barrier flag is the companion that makes this meaningful.

**OOM recovery / solve delegation**: `execute_case_study()` calls `lego.solve_model(tee=tee)`. This means the main solve follows the case study's `pSolver` ; the OOM/WorkLimit recovery below only applies on the Gurobi path. All recovery lives in `LEGO.solve_model()`: if `optimizer.solve()` throws, it catches the exception, checks `SolCount`, and calls `optimizer.load_vars()` to recover any solution found before the crash; if no results object exists it builds a synthetic `SolverResults` with `status=error` and `termination_condition="Out of Memory"` only when the exception is a `gurobipy.GurobiError` with `errno == GRB.Error.OUT_OF_MEMORY` (left unset otherwise). `solve_model()` **raises by default** (`raise_on_no_solution=True`); if it is set to False, on an error with no feasible solution, it logs via `printer.error` and returns the synthetic result so the batch continues. It sets `lego.has_solution`, `lego.work_units`, `lego.mip_gap`, and `lego.results` as side effects; `work_units`/`mip_gap` are extracted in all cases (even after a crash). All solve call sites (main, regret, invest-regret, operational, operational-regret) gate `write_results` on `lego.has_solution` and keep the post-solve `termination_condition` match (incl. `log_infeasible_constraints`) running unconditionally. The `has_solution` gate is essential — without it the regret/invest-regret paths would write empty `-regret`/`-invest-regret` sqlites that pollute the `--no-overwrite` status check. Per-option logging ("Setting work limit to X", etc.) stays in the caller / `_apply_solver_options` — `solve_model()` applies options silently to avoid double-logging. `EvaluateMarkov.py` computes `achieved_mip_gap` preferentially from `lower_bound`/`upper_bound`, but falls back to the direct `mip_gap` column when bounds are absent or NaN (typical for OOM runs).

**WorkLimit termination condition**: When `result.solver.status == SolverStatus.error` and a solution exists (work-limit hit), `termination_condition` is patched to `"WorkLimit reached"` only if `optimizer._solver_model.Status == gurobipy.GRB.WORK_LIMIT` — confirmed from Gurobi, not inferred from whether `--work-limit` was passed. This patching (and the `load_solutions=False` + manual `model.solutions.load_from()` flow) lives in `LEGO.solve_model()`, shared by the main, regret, and invest-regret solves — without it, `gurobi_persistent.solve()` with the default `load_solutions=True` would crash with "Cannot load a SolverResults object with bad status: error" whenever a solve hits a work limit.

**invest-regret vGenInvest source**: When the main solve ran (`case_skipped=False`), `vGenInvest` is read from the in-memory model — valid even after a non-optimal solve (e.g. work limit), because `solve_model` loads the partial solution into the model, so the values match what was written to the sqlite. Only when `case_skipped=True` is it loaded from disk: the exact `{file_prefix}.sqlite` if present, else the best sibling's file from the smart skip (see `--no-overwrite` Part 2).

**Three regret variants** (all re-solve the full-hourly Truth model; all skip the `"Truth "` edge handling, whose regret is degenerate):
- `--calculate-regret` (`-regret.sqlite`, `run_type="regret"`): hard-fixes `vGenInvest` **and** soft-fixes `vCommit`, both from the edge handling's **main** run. The `vCommit` soft-fix is `add_UnitCommitmentSlack_And_FixVariables`; the `vGenInvest` hard-fix was added on top (sourced in-memory from `model.vGenInvest` when the main solve ran, or loaded from `{file_prefix}.sqlite` alongside `vCommit` when `case_skipped`). **Semantic change**: this used to fix `vCommit` only (investment free) — pre-existing `-regret.sqlite` files therefore have different semantics and should be regenerated. Its `--no-overwrite` check is now **status-based** (skip only if the existing `-regret.sqlite` is `optimal`, like the operational/invest-regret checks), replacing the old existence-only check — so a work-limited or old-semantics file is re-run.
- `--invest-regret` (`-invest-regret.sqlite`): hard-fixes `vGenInvest` from the main run only; `vCommit` free. Unchanged.
- `--operational-regret` (`-operational-regret.sqlite`, `run_type="operational-regret"`): hard-fixes `vGenInvest` to the **Truth** investment (same 0.5-threshold decision the operational runs use) and soft-fixes `vCommit` to the edge handling's **operational** run. See its own note below.

**`--operational-regret`**: requires `--operational` (validated fail-fast in `main()`); it consumes each edge handling's operational `vCommit`, which only exists once the operational pass has run. Implemented as an extra block *inside* `execute_operational_runs`, right after each edge's operational solve — the one place where both `truth_invest` (resolved at the top of the function) and the operational `vCommit` are available together. The operational `vCommit` source is, in priority order: `op_lego.model` (in-memory, when the operational solve ran this iteration), else the exact `{op_prefix}.sqlite` if the operational run was exact-file-skipped, else the smart-skipping sibling's `.sqlite` when the operational run was sibling-skipped — captured into `op_sibling_skip_file` from `_should_skip_smart`'s third return value (mirrors the invest-regret `sibling_skip_file` pattern). The sibling differs only in `work_limit`, so its `vCommit` may be work-limited rather than optimal (Rule-2 skips fire on any *clean* sibling, incl. `WorkLimit reached`), but it is a feasible commitment and is soft-fixed via `add_UnitCommitmentSlack_And_FixVariables`, so optimality is not required. Only when none of the three sources exists is operational-regret skipped with a message. `op_lego` and `op_sibling_skip_file` are both reset at the top of each loop iteration so a `case_skipped` iteration never reuses the previous edge's model/file. The full-hourly Truth base is resolved once into the `truth_base` variable (declared before the edge loop, stays `None` until first actual need) — `lego_models["Truth "]`, or `_build_full_hourly_truth_lego(cs, ...)` under `--skip-truth` — then reused (`.copy()`-ed) per edge, so a fully no-overwrite-skipped batch never pays for the build. The `vCommit` slack mapping uses the **edge handling's** `lego.cs.dPower_Hindex` (maps the reduced `(rp,k)` onto the Truth full-hourly `k`), not the Truth base's. Like the other regret variants, output files are **not** appended to `sqlite_files`/`sqlite_labels`. `--no-overwrite` skips an existing `-operational-regret.sqlite` only when it is `optimal`. `operational_regret` is plumbed `main → execute_case_studies → execute_case_study → execute_operational_runs` (all default `False`); it is **not** in `run_params`/`_SIBLING_COMPARE_KEYS` (the per-file `run_type` distinguishes it, and the `-operational-regret.sqlite` suffix ends in `-regret.sqlite` so the `_find_sibling_runs` glob already excludes it from main-run sibling discovery).

**`edge_handling` value in run_parameters**: The stored string is the model dict key after `.strip().replace('.', '').replace(' ', '')` — e.g. `"NoEnf"`, `"Cyclic"`, `"Markov"`, `"Markov-Strict"` (the hyphen survives: normalization only strips periods and spaces). Use this normalized form when filtering or grouping SQLite results.

**Evaluation grouping**: `EvaluateMarkov.py` groups results by `(case_study_directory, filter_zone, limit_k, clusters, shift, stretch_demand, scale_vres, scale_invest_cost, thermal_invest_only, merge_generators, shift_tm, perturb_tm, relax_count, no_investment, rmip, no_crossover, force_barrier, mip_gap, network, commit_consumption, startup_consumption)`. A new run parameter that should split comparison groups must be added to this grouping — and to `load_file_metadata` so it is read from SQLite. When implementing a new run parameter, proactively ask the user whether and how it should be added to `EvaluateMarkov.py` before closing the task.
**Capacity investment table**: `EvaluateMarkov.py` prints a second investment table showing `vGenInvest[g] * pMaxProd[g]` (invested capacity) keyed as `vCapInvest` / `vCapInvest[{tec}]`. Both investment tables include `%` columns relative to the Truth entry. If `pMaxProd` is missing from the SQLite file, the capacity table is silently skipped.
**Parallel file loading**: `EvaluateMarkov.py` loads all SQLite files concurrently via `ProcessPoolExecutor` — `_load_file` must stay module-level so it can be pickled. Each worker opens its own connection. Entry ordering after load is non-deterministic but is normalised by the per-group sort before printing.
**SQLite file discovery + per-kind tables**: `EvaluateMarkov.py` discovers **all** `MK-*.sqlite` files; `_load_file` classifies each by suffix into `main`, `operational`, `regret`, `invest_regret`, or `operational_regret` (full metadata + results loaded for every kind). Suffix routing order matters: `-operational-regret.sqlite` and `-invest-regret.sqlite` both end in `-regret.sqlite`, so both are tested **before** the bare `-regret.sqlite`, which is tested before `-operational.sqlite`. Each non-main kind is grouped by `_group_key` (same keys as the main table; `run_type` is **not** a grouping key — the kind routing separates them) and printed as its **own** table per group, after the main and operational tables. The old inline `Regret Obj.` / `Invest-Regret Obj.` columns on the main table were removed in favour of these separate tables. Regret tables contain no `Truth` row (Truth is never a regret run), so `print_comparison_table` falls back to the Markov entry as the `%` reference there (flagged "Differences compared to Markov result").

**`CompareMarkov.py` design**: Produces up to 28 boxplot PNGs — 14 logical plots, each emitted twice by the `emit()` closure inside `render_plots()` (full + a NoEnf-excluded `_noNoEnf` twin; the twin just passes a reduced `edges` list to the plotter, the boxes are built once). `render_plots()` holds all 14 plot definitions and takes a `fname_suffix`/`title_suffix` pair so `--separateClusters` can call it once per cluster count. The active edge list is `EDGE_ORDER = ['NoEnf','Cyclic','Markov']` plus `EDGE_STRICT = 'Markov-Strict'` when `--markov-strict` is set (the stored `run_parameters.edge_handling` for the strict variant is the hyphenated `'Markov-Strict'` — the hyphen survives the `.strip().replace('.', '').replace(' ', '')` normalization, which strips only periods and spaces). `edges` is threaded into every box builder and into `make_boxplot_figure`, which takes the `edges` to draw, an optional `ref_line` y value (replaces the old `zero_line` bool), and a `symmetric_y` bool: deviation/regret pass `ref_line=0, symmetric_y=True`; the work-units plots pass neither (no reference line — the old `ref_line=100` on the relative work-units plots was removed because it dwarfed the small values). **Two work-units variants per run type**: `build_runtime_boxes` (absolute, *appends* per entry) and `build_runtime_relative_boxes` (`work_units / truth_work_units * 100`, grouped by `(tm, subcase)` against the same-kind Truth like the deviation builder). Relative work-units need a Gurobi `work_units` value on *both* the edge and Truth runs → empty under HiGHS (local). Subplot order is `_tm_sort = (shift_val, perturb_val)` with unset → `-inf` (base, perturbTM, shiftTM, shiftTM+perturbTM, …). `RichHelpFormatter` is imported unguarded (matches `EvaluateMarkov.py`; rich_argparse is a hard dep) and used directly in `main()`. The rest: Imports only `_load_metadata_from_conn` from `EvaluateMarkov` (via `sys.path` to parent) for metadata parsing; everything else is local and reads *only what each plot needs* (`work_units` from `solver_statistics`, a SQL-aggregated weighted `vShutdown` sum via temp weight tables like `EvaluateMarkov`, and the `objective`). Files are classified by suffix in `_load_compare_file` into three regret kinds plus operational/main: `-invest-regret.sqlite` and `-operational-regret.sqlite` **must** both be tested before the bare `-regret.sqlite` (both end with `-regret.sqlite`); each regret kind returns `(termination, objective)`. In `load_all`, `invest_regret_obj` and `regret_obj` are keyed by the base **main** file (`f.replace("-invest-regret.sqlite"/"-regret.sqlite", ".sqlite")`), while `operational_regret_obj` is keyed by the base **operational** file (`f.replace("-operational-regret.sqlite", "-operational.sqlite")`); each has a paired `_term` map for the optimal-only filter. `load_all` returns `(main_entries, operational_entries, invest_regret_obj, regret_obj, operational_regret_obj)`. `_load_compare_file` now reads `Objective` for **operational** entries too (not just main) — it is the Truth-operational reference for the operational-regret plots. `build_regret_boxes(base_entries, regret_obj, mode, edges)` is generic over all three regret variants: invest-regret and regret pass `main_entries` (vs Truth-main objective), operational-regret passes `operational_entries` (vs Truth-operational objective); the regret value is looked up by each base entry's own `file`, so reference and regret always come from the same run kind. Plots **E** (invest-regret), **F** (regret), and **G** (operational-regret) are each emitted absolute + relative (+ `_noNoEnf` twins). `-operational.sqlite` → operational; everything else → main. Loaded concurrently with `ThreadPoolExecutor` (no pickle constraint, unlike `EvaluateMarkov`'s ProcessPool). Subplot axis is `(shift_tm, perturb_tm)`; each box aggregates the *sub-cases* keyed by `SUB_CASE_KEYS` (all run params except the TM ones — note `shift` (time-series shift) is a sub-case key and is **distinct** from the `shift_tm` subplot axis). Box builders: `build_runtime_boxes` *appends* `work_units` per entry (safe because filenames are unique per `(tm, subcase, edge)` — `work_limit` is not in the filename, so a work-limited and an unlimited re-run share a name and only one exists on disk); the truth-referencing builders (`build_runtime_relative_boxes`, `build_deviation_boxes`, `build_regret_boxes`) all sit on the shared generator `_iter_vs_truth(entries, edges, edge_value, truth_value=None)`, which groups `(tm → subcase → {edge: entry})` and yields `(tm_key, edge, truth_ref, value)` — the grouping silently keeps only the last entry if a `(tm, subcase, edge)` ever collides (it shouldn't for real data; it *does* for `FindInvestmentDataset` outputs, which all share one `case_study_directory` → use those only as a runtime-path/render smoke test, not for deviation counts). The deviation and regret builders are thin wrappers around `_diff_boxes(pairs, mode, truth_skip)` (relative `(v−t)/|t|·100` with a `t==0` skip / absolute `v−t`): deviation passes `truth_skip=(None,)`, regret `truth_skip=(None, 0, -1)` — that tuple difference *is* the old per-builder skip semantics, don't unify it. Deviation reference is the **Truth entry of the same kind**: operational plots compare against Truth-operational, investment plots against Truth-main; `relative` mode skips sub-cases where Truth==0, `absolute` does not. Invest-regret (E) references Truth-main's `Objective` and, like the deviation builder, is emitted in two modes via `build_regret_boxes(main_entries, invest_regret_obj, mode, edges)`: `relative` → `(iregret − truth_obj)/|truth_obj|·100` [%] (`compare_invest_regret_relative.png`), `absolute` → `iregret − truth_obj` in native objective units (`compare_invest_regret_absolute.png`). Both pass `ref_line=0, symmetric_y=True`. **MIP-gap noise band (invest-regret only)**: both invest-regret emits also pass a `gap_fn` to `emit()`, which calls `invest_regret_gap_band(main_entries, invest_regret_obj, mode, eds)` *per drawn edge list* (so the full and `_noNoEnf` twins get correctly-scoped bands) and forwards the resulting `(lo, hi)` to `make_boxplot_figure` as `gap_band`. It uses the **requested** `mip_gap` run-parameter (not `achieved_mip_gap` — that varies per run and would never collapse the relative band to a line), iterating the same `(tm → subcase → {edge})` grouping and the same `truth_obj in (None,0,-1)` skip as the regret boxes, restricted to the drawn `edges` and to points that actually have a regret objective + a `mip_gap`. Per point the magnitude is `mip_gap*100` (relative — pure percent, independent of objective) or `mip_gap*|invest-regret obj|` (absolute — uses the *plotted result's* invest-regret objective, so it differs between sub-cases); the band is `(min, max)` over all such magnitudes, or `None` when no point carries a `mip_gap`. `make_boxplot_figure` draws it light red (`GAP_COLOR`) on every subplot as a filled `axhspan` at `[lo,hi]` and a mirror at `[-hi,-lo]` (`zorder=0`, behind the boxes); when `hi-lo < 1e-9` (the relative plot's uniform-gap case) it degenerates to a pair of `axhline`s at `±lo`. The band is suppressed under log scale, and the `symmetric_y` limit is widened to include `|gap_band[1]|` so the band stays visible even when every regret is tiny. Unlike the deviation builder, the guard `truth_obj in (None, 0, -1)` (the EvaluateMarkov "no objective" sentinel) is applied in *both* modes — a zero/sentinel Truth objective is never a meaningful absolute reference here — so the two regret plots aggregate over identical sub-cases. Default filter is `termination_condition == 'optimal'` (also applied to the invest-regret sibling via its own termination) unless `--include-nonoptimal`. `Truth` is never a box (it is the reference); the boxes drawn are exactly the active `edges` list (Markov-Strict only with `--markov-strict`). Y-axis is **linear by default**; `--logscale` switches only the work-units plots to log (and `make_boxplot_figure` further guards log behind all-positive data). Signed plots (deviation/regret) set `symmetric_y=True`, which centres the shared y-axis on 0 — limits are `±1.05·max|value|` (computed from the drawn data, fliers included), so equal magnitudes above and below the 0 reference read the same; the limit is skipped under log scale (always all-positive). No legend (x-tick labels + consistent colors suffice); each box is annotated with `n=<#points>`. **Presentation**: figures carry **no** `suptitle` (removed — `title` is still passed but used only for the `[skip]` log line and the `_noNoEnf` twin's derived title, never drawn), so `tight_layout()` uses the full figure. Subplot titles come from `_tm_label(shift_tm, perturb_tm, base_label)`: a shifted-TM subplot reads `"Transition Matrix\nshifted by {N}"` (two lines) and the unperturbed subplot uses `base_label` = the **dataset name** from `_data_label(entries)` (`' / '`-joined if several distinct, `'(base)'` fallback when none is stored — as for `FindInvestmentDataset` outputs), threaded `render_plots → emit → make_boxplot_figure(data_label=...)`. The dataset name comes from `_dataset_name(case_study_directory)`, **not** a raw basename: `Markov.py`'s `execute_case_studies` nests one preprocessing subfolder per step onto the dataset dir (`filterZone*/`, `limitK*/`, `shift*/`, `stretchDemand*/`, `mergeGenerators/`, `{N} clusters/`), so e.g. `data/RTS-GMLC/7 clusters/` must strip the trailing `7 clusters` to yield `RTS-GMLC`; `_dataset_name` pops trailing components matching `_PREPROCESSING_SUBFOLDER` (any depth; the regex also matches a bare `data` so the top-level `data/` folder is never returned as the label) then takes the basename (so a mix of cluster counts collapses to one dataset label rather than `3 clusters / 5 clusters / …`). X-tick box labels go through `EDGE_LABELS` (display-only: `NoEnf → "No Enf."`; the internal edge keys are unchanged for lookups/colors). Empty categories are skipped with a `[skip] … no data` message rather than crashing on `plt.boxplot([])`. Note: `work_units` is `None` under non-Gurobi solvers (e.g. HiGHS locally) → A/C are empty in local tests but populate on the Gurobi server runs. `make_boxplot_figure` closes its figure before returning (no return value) so `--separateClusters` batches don't accumulate open matplotlib figures.

**`CompareMarkov.py` filters (`--nrOfClusters`, `--separateClusters`, `--tm`)**: All three operate on the loaded *entries* only (`filter_entries(entries, cluster_filter, tm_specs)`); the regret objective maps are never filtered — they are only looked up via each surviving entry's own `file`, so stale keys are harmless. `--nrOfClusters 3,5,7` matches against the **int**-typed `clusters` metadata; entries with `clusters=None` (unclustered) are dropped whenever the filter is given. `--tm` specs (repeatable and/or comma-separated) are parsed by `parse_tm_spec` into `(shift, perturb)` pairs where each side is `float | None | '*'`; `_matches_tm` normalizes the stored entry values through `_tm_value` first — important because `shift_tm` is stored as **str** and `perturb_tm` as float, so both sides go through `float()` and `--tm 2:0.2` matches `shift_tm='2'`. `_tm_value` (None/'None' → None, else float) is also reused by `_tm_sort` and `_tm_label`. `--separateClusters` calls `render_plots()` once per distinct `clusters` value present after filtering (sorted ascending, `None` last) with `fname_suffix=f"_clusters{value}"` — so unclustered runs get `_clustersNone` — and a ` — N clusters` / ` — no clustering` title suffix. Malformed `--nrOfClusters`/`--tm` values are rejected via `parser.error` in `main()` (the camelCase flag names were requested explicitly; the rest of the CLI is kebab-case).

**`NonBinarityMarkov.py` design**: Reports how often the integrality-constrained variables actually take non-integer values across a folder of `MK-*.sqlite` files. `INTEGRALITY_VARS = ['vLineInvest', 'vGenInvest', 'vCommit', 'vStartup', 'vShutdown']` — exactly the variables declared `pyo.Binary`/`NonNegativeIntegers` that are written to SQLite (storage's `bChargeDisCharge` and the SOCP indicator are Binary too but **not** persisted, so they're absent). Under the Markov edge handling `vCommit`/`vStartup`/`vShutdown` are deliberately relaxed to a continuous domain for non-edge timesteps (`vUC_domain` in `thermalGen.py`), so fractional values for those vars on Markov runs are *expected* — quantifying that is the point of this script. Per variable it computes, in pure SQL (one aggregate query per table), the **count** of rows deviating from the nearest integer by more than `--tol` (default `1e-6`), the **summed** deviation `Σ|v-round(v)|` over those fractional rows (`SumDev` column — distinguishes many-barely-fractional from few-badly-fractional), and the **max** single deviation (`MaxDev`) — never transferring the large `vCommit` etc. tables to Python. The per-variable columns are counts (`fractional`); `SumDev`/`MaxDev` are reported only as group/file aggregates, not per variable. Missing tables (e.g. no thermal gens) are skipped via `_table_exists`. **Reuses CompareMarkov's filtering verbatim** by importing `filter_entries`, `parse_tm_spec`, `_tm_label`, `_tm_sort`, `EDGE_ORDER`, `EDGE_STRICT` — so `--nrOfClusters`/`--separateClusters`/`--tm`/`--include-nonoptimal` behave identically (importing CompareMarkov also pulls in matplotlib + sets up the printer, harmless here). File-kind classification (`_classify_kind`) mirrors CompareMarkov's suffix routing order (`-invest-regret`/`-operational-regret` before bare `-regret`, then `-operational`, else main). Unlike CompareMarkov, regret-kind files are loaded with full metadata (not just objective) so they can be filtered/grouped like any other entry. Output: one aggregated table per run kind, rows = `(shift_tm, perturb_tm)` × `edge_handling` (sorted by `_tm_sort` then `EDGE_DISPLAY_ORDER`), columns = per-variable fractional counts + totals + `%Frac` + `FilesWithFrac` + `MaxDev`; `--per-file` adds a row-per-file table. No `--markov-strict` flag — all edge handlings present (incl. `Markov-Strict`, Truth) are always reported. **`.txt` saving**: the whole report is teed to `nonbinarity_report.txt` (in `--output-dir`, default the input folder; `--no-txt` to skip) via the `Printer`'s `set_logfile()` — the report is built entirely from `printer` calls (`_print_table` → `printer.information`, `printer.rule`), so the logfile captures the plain-text equivalent. The block sets `printer.add_timestamp_to_logfile = False` for a clean dump, **truncates** any existing file first (`set_logfile` appends), and restores `add_timestamp_to_logfile` + clears the logfile in a `finally` (so a later `printer` call isn't appended to the report). This is the one place these tools use the logfile tee rather than writing text explicitly — `CompareMarkov`'s results table writes its `.txt` directly because that output is a plain string, not a stream of `printer` calls.

**`--no-overwrite` check**: Two-stage logic applied per edge-handling type:
1. **Exact file exists** (`{file_prefix}.sqlite`): read its `solver_statistics.termination_condition`. If `'optimal'` → skip. If anything else (e.g. `'WorkLimit reached'`, `'infeasible'`, `None`/unreadable) → re-run and overwrite. The same status-based check applies to the `-invest-regret.sqlite` file (see Part 2 below).
2. **Exact file absent**: `_find_sibling_runs()` searches for SQLite files in the same directory sharing all `run_parameters` except `work_limit`. `_should_skip_smart()` then decides:
   - Any sibling solved to optimality → skip.
   - Otherwise, split siblings into *clean* (termination_condition ∈ `{'WorkLimit reached', 'optimal'}` — solver genuinely consumed its budget) and *not-ok* (killed / OOM / error — budget not really consumed).
   - If *all* siblings are not-ok → re-run in any case.
   - Otherwise, find the best clean sibling (highest `work_limit`; `None` = unlimited = ∞). If current `work_limit` is **not strictly higher** than the best clean sibling's → skip. If strictly higher → re-run.
   - Consequence: unlimited current WL > any finite sibling WL → re-run; finite current WL vs. unlimited clean sibling → skip; equal WLs → skip.
   If the main file is missing due to a smart skip, regret is also skipped for that edge-handling type; invest-regret instead falls back to the sibling's file (see Part 2), and operational-regret falls back to `op_sibling_skip_file` (see its own note).
- **Part 2 — invest-regret no-overwrite**: The `-invest-regret.sqlite` file check mirrors the main-file logic. If it exists and `termination_condition == 'optimal'` → skip. If it exists with any other status → re-run (log the status). `vGenInvest` source priority when `case_skipped=True`: (1) the exact `{file_prefix}.sqlite` if it exists, (2) `sibling_skip_file` for any sibling-skip (both Rule-1 optimal and Rule-2 WL-comparison). Invest-regret is only skipped when `sibling_skip_file is None` (which only occurs when all siblings had non-ok status and the re-run path was taken — i.e. `case_skipped` would be False). `_should_skip_smart` returns a third value `sibling_file` — the best sibling's path — for both skip rules; `None` only on re-run paths.

**`--operational`**: Additive — produces an extra run per built edge-handling model (Truth, NoEnf, Cyclic, Markov, +Markov-Strict if `--enable-strict-markov`), on top of the regular runs. Implemented as a separate pass (`execute_operational_runs`) after the main solve loop in `execute_case_study()`, because each operational run needs the Truth investment decision, which is only known once Truth has been solved. Each run copies the corresponding already-built (and possibly already-solved or no-overwrite-skipped) model via `lego.copy()`, re-stamps solver options with `_apply_solver_options`, fixes `vGenInvest[g] = 1 if truth_invest[g] > 0.5 else 0` (only `vGenInvest`, matching `--no-investment`; default-missing → 0, which differs from invest-regret's default-1), and re-solves with `already_solved_ok=True, raise_on_no_solution=False`. Files are `MK-{case}-{edge}-operational.sqlite` (suffix, like `-regret`/`-invest-regret`); run_parameters get `run_type="operational"`. `--operational` is **not** stored in `run_params` (it is not a group-splitting param — the per-file `run_type` distinguishes operational from main). Truth investment must come from an *optimal* result: in-memory Truth only if its solve reached `pyo.TerminationCondition.optimal` (a work-limited/OOM in-memory Truth is rejected with a warning, same bar as sqlite), else the best optimal Truth `.sqlite` via `_find_optimal_truth_file` (exact file first, then siblings differing only in `work_limit`; `termination_condition == 'optimal'` only); if neither, all operational runs are skipped with an error and the batch continues. Under `--skip-truth` the Truth model is absent from `lego_models`; `execute_operational_runs` then prepends a `("Truth ", None)` entry and, **lazily** (only when the `--no-overwrite` check doesn't skip it, to avoid a wasted expensive build), rebuilds the full-hourly Truth model via `_build_full_hourly_truth_lego(cs, thermal_generator_relaxed)` — `cs.to_full_hourly_model(inplace=False)` + `build_model()` + the same UC relaxation the main loop applies — and re-solves it with the fixed investment (so Truth-operational's runtime is comparable to the other operational runs, per the user's intent). This requires `cs` and `thermal_generator_relaxed` to be plumbed from `execute_case_studies` through `execute_case_study` into `execute_operational_runs` (both default `None`; when `cs is None`, Truth-operational is skipped with a warning and the others still run). The on-demand Truth lego is used directly (no `.copy()`, since it is freshly built and not part of the returned `lego_models`); in-memory source models are `.copy()`-ed as usual. **`run_type` was added to `_SIBLING_COMPARE_KEYS`** so `--no-overwrite` sibling discovery treats operational and main files as distinct (operational files end in `-operational.sqlite`, not the `-regret`/`-invest-regret` the glob excludes, so they would otherwise be matched as main-run siblings); backward-compatible because old main files lack the column → `params.get('run_type','None') == 'None'` matches `current_edge_params.get('run_type') is None`. `EvaluateMarkov.py` routes `-operational.sqlite` through a new `_load_file` kind `'operational'` (full meta+results, like `'main'`) and prints them in a **separate per-group table** ("Operational runs ...") via the shared `print_comparison_table`; grouping/entry construction are factored into `_group_key`/`_build_entry`, and the print loop iterates the union of all kinds' group keys. `CompareMarkov.py` loads operational files too (`-operational.sqlite` → operational in `_load_compare_file`) and emits a parallel set of "Operational runs" plots alongside the investment-run plots — see the `CompareMarkov.py` design note for the full data flow.

**`CompareMarkov.py` results table**: after rendering the PNGs, `report_results_table()` emits the mean/median/min/max *behind* each boxplot as a numeric table for the paper — printed to the terminal (plain `print`, to avoid rich re-wrapping the markdown) **and** saved as `compare_markov_results.txt` (+ `.csv`) in the output dir (`_clusters{N}` suffix under `--separateClusters`, mirroring the plot filenames). Disable with `--no-results-table`. It reuses the *same* box builders the figures use (`build_deviation_boxes`, `build_runtime_relative_boxes`, `build_regret_boxes`), so the numbers match the plots exactly; `_aggregate_boxes` turns a `{tm_key: {edge: [vals]}}` box dict into `{(tm_key, edge): {mean,median,min,max,n}}`. Rows are keyed by `(TM_variant, method)` where `TM_variant = tm_variant_label(tm_key)` (`shift_tm` unset → `"Original"`, else `"Shift{N}"`, `+perturb{p}` appended when `perturb_tm` set) and `method` is the `edge_handling` ordered by `EDGE_DISPLAY_ORDER` (note: this module-level `EDGE_DISPLAY_ORDER = ['NoEnf','Cyclic','Markov','Markov-Strict']` has **no** `'Truth'`, unlike `NonBinarityMarkov`'s same-named constant — Truth is the reference, never a table row). **The LEGO objective is already in M EUR** (Truth objective ≈ 1900), so the absolute invest-regret box value (`build_regret_boxes(..., 'absolute', ...)`, native units) *is* the regret in M EUR with no conversion. **vStartup augmentation**: the plots only load `vShutdown`; `augment_startup()` attaches an annual-weighted `vStartup` sum (via `_weighted_var_sum`, parallel `ThreadPoolExecutor`) to each entry in place — **idempotent** (skips entries already carrying `vStartup`) so the per-cluster `--separateClusters` re-aggregation is cheap — so `build_startup_deviation_boxes` (a thin `_iter_vs_truth`/`_diff_boxes` wrapper mirroring `build_deviation_boxes`) can report NoEnf's start-up deviation, which differs from its shut-down deviation (Cyclic/Markov have start-ups == shut-downs). Primary `oper_dev`/`wu_oper` columns come from `operational_entries`; with no `--operational` runs those are empty and the diagnostics `invest_run_shutdown_dev_mean_pct` (deviation on the *main* runs) is the labelled fallback. Per-metric `n` legitimately differ (an optimal main run can have a non-optimal Truth or no invest-regret/operational sibling), so the headline `n_runs` is the operational-deviation count and the diagnostics table breaks out `n_oper_dev`/`n_startup`/`n_regret`/`n_wu_oper`/`n_wu_invest` separately — don't assume one shared `n`. Empty-cell placeholder is ASCII `"n/a"` (not an em-dash) to stay clean under the Windows console encoding.
