# CLAUDE.md

This file provides guidance to Claude Code when working on MK experiment scripts.
See [`README.md`](README.md) for usage, key concepts, and CLI parameter reference.

Two scripts: `Markov.py` (runs the experiments, incl. the per-run analysis written into every sqlite) and
`EvaluateMarkov.py` (all evaluation, as subcommands `tables` / `plots` / `summary` / `all`).

## Non-obvious patterns — `Markov.py`

**Shared helpers — use them instead of re-implementing**: every solve goes through `_solve_and_write` (solve with `raise_on_no_solution=False`, write only if `lego.has_solution`, log the termination condition — the `has_solution` gate is essential, an empty sqlite would pollute the `--no-overwrite` status checks). Every regret-style run (regret, invest-regret, operational-regret, original-*) goes through `_solve_fixed_decisions` (copy base model → `_apply_solver_options` → `_fix_gen_invest` → optional `_soft_fix_commit` → `_solve_and_write` → `gc.collect()`). `--no-overwrite`: `_existing_optimal(file)` for single output files (skip only if `optimal`, otherwise log status and re-run), `_no_overwrite_check(prefix, run_params, edge_params)` for main/operational runs (exact file, else sibling smart check; returns the sibling file). `_normalize_edge` turns the model dict key into the stored `edge_handling` (`.strip().replace('.', '').replace(' ', '')` → `"NoEnf"`, `"Markov-Strict"` — the hyphen survives); use this normalized form when filtering or grouping SQLite results.

**Solver options flow**: A CLI arg (e.g. `--mip-gap`) sets a key in `cs.dGlobal_Parameters` (e.g. `"pMIPGap"`) via `_apply_case_modifications`. `LEGO._build_model()` reads this and stores it as a plain attribute on the Pyomo model (e.g. `model.pMIPGap`), which `LEGO.solve_model()` applies to `optimizer.options`. Copied models (all regret/operational runs) get the attributes re-stamped by `_apply_solver_options(lego, run_params)` (defensive against deepcopy edge-cases; also logs them). When adding a new solver option, update `_apply_case_modifications`, `LEGO.solve_model()`, and `_apply_solver_options()`.

**Case-study modifications and run parameters are shared**: `execute_case_studies` builds one `modifications` dict that feeds both `_apply_case_modifications([cs, cs_original], **modifications)` (applies options/data changes identically to the RP and the original case study, returns the identifier parts) and `_build_run_params(..., **modifications)` (the `run_parameters` dict; options at their default are stored as `None`). `execute_original_truth` uses the same two functions. When adding a new data modification or run parameter, add it to these two functions (and to the `modifications` dict / `main()` call of `execute_original_truth`), not inline. `_cap_min_up_down_times` caps the original model to the RP length (`len(cs.dPower_WeightsK)`), not to its own K count, so RP models and original differ only in the time series. `_select_relaxed_generators` must run **after** the cap (it sorts by MinUp+MinDown, which the cap changes).

**Resource-management Gurobi options** (`--node-file-start`, `--node-file-dir`, `--threads`): Same plumbing as `--mip-gap`, but deliberately **NOT** in the identifier (filenames don't change between memory configurations), **NOT** in `_SIBLING_COMPARE_KEYS` (a re-run with different node-file settings is the same sibling) and **NOT** in the `EvaluateMarkov.py` grouping. Stored in `run_parameters` for traceability only. `--node-file-dir` without `--node-file-start` raises in both `main()` and `execute_case_studies()`. `_node_file_dir_with_pid` *always* appends `str(os.getpid())` to the base path (user-supplied or `./gurobi-nodes/`) so parallel spawns never collide; the post-join value is what is stored in `pNodeFileDir` and `run_parameters`. `LEGO.solve_model()` auto-creates the dir; Gurobi cleans its contents on normal exit, the per-PID folder persists.

**Preprocessing order in `main()`**: `--filter-zone` (`filterZone{zone}/`, exact match on `z` — merged-bus zones like `"R1_R2"` are not matched by `"R1"`) → `--limitK` → `--shift` → `--stretch-demand` → `--merge-generators` (`mergeGenerators/`) → clusters (`{N} clusters/`). Each step writes a subfolder (unscaled `CaseStudy`) that is the base of the next; `--reuse-inputfiles` reuses existing folders. `--scale-vres`, `--scale-invest-cost` (ThermalGen/VRES/Storage `InvestCostEUR`; line investment unaffected), `--thermal-invest-only` (`ExisUnits=1`, `EnableInvest=0` on VRES and Storage), `--network`, the consumption multipliers and the solver options create no subfolder — they are applied in memory by `_apply_case_modifications`.

**`--shift-tm` / `--perturb-tm`**: Applied in `execute_case_studies()` to the base `cs` before the edge-handling copies, so all models (incl. Truth, built from Hindex) see the same modified Hindex/TM. `shift_transition_matrix(n)` cyclically shifts every row of the absolute TM right by `n`, normalizes, resamples a chronological RP sequence (seeded with `n`) and rebuilds `dPower_Hindex`, `dPower_WeightsRP` and the TM attributes; `perturb_transition_matrix(r)` interpolates each row: `(1-r)*orig + r*random`. Both are in the sibling-compare keys and the identifier (`shiftTM2`, `perturbTM0.5`).

**`--no-crossover` and `--force-barrier` are coupled**: `main()` raises if exactly one is set (disabling crossover only makes sense with barrier).

**OOM / WorkLimit recovery**: all recovery lives in `LEGO.solve_model()` (see `LEGO/CLAUDE.md`): partial solutions are loaded after a work-limit hit (`termination_condition` patched to `"WorkLimit reached"` only if Gurobi's `Status == GRB.WORK_LIMIT`), a synthetic result with `"Out of Memory"` is returned for a Gurobi OOM without solution, and `lego.results` / `has_solution` / `work_units` / `mip_gap` / `solver_attributes` are always set. `Markov.py` always calls it with `raise_on_no_solution=False` (via `_solve_and_write`). Consequently `lego.results is not None` means "solve attempted in this session" — `_edge_main_decisions` relies on that. `EvaluateMarkov.py` computes `achieved_mip_gap` from `lower_bound`/`upper_bound`, falling back to the `mip_gap` column (OOM runs have no bounds).

**Regret runs and their decision source** (all re-solve a full-chronological model; all skip the `"Truth "` edge handling, whose regret is degenerate — except `-original-invest-regret`):
- `--calculate-regret` (`-regret.sqlite`, `run_type="regret"`): hard-fixes `vGenInvest` **and** soft-fixes `vCommit` from the edge handling's main run. (Pre-existing `-regret.sqlite` files from before `vGenInvest` was also fixed have different semantics — the status-based `--no-overwrite` re-runs non-optimal ones only.)
- `--invest-regret` (`-invest-regret.sqlite`): hard-fixes `vGenInvest` only.
- `--operational-regret` (see below).
Both main-run variants are one loop over `regret_variants` in `execute_case_study`; they need the in-memory Truth model (`--skip-truth` → one warning, no regret runs). Decisions come from `_edge_main_decisions(lego, file_prefix, run_params, normalized, need_commit)`: the in-memory model if `lego.results is not None` (main solve ran this session — valid even after a work-limited solve, since the partial solution is loaded; `None` if the solve produced no solution), else the exact `{file_prefix}.sqlite`, else the sibling `_should_skip_smart` skipped for (differs only in `work_limit`). File `vCommit` values are loaded into the (unsolved) in-memory edge model. Default for generators missing in the decisions is 1 (`gen_invest_default`).

**Pyomo stale flags are global**: loading any solution marks the variables of *all other* models stale, and `add_UnitCommitmentSlack_And_FixVariables` maps stale values to 0. `_soft_fix_commit` therefore re-marks the source `vCommit` values `stale = False` right before the soft-fix (without it, original-regret runs pinned all units off → ~99% load shedding). The soft-fix maps the full model's `k####` → `h####` along the **edge's** Hindex (`lego.cs.dPower_Hindex`), which matches the clustered Hindex labels (`apply_kmedoids_aggregation` writes `p = h{day*24+k}` in chronological order).

**`--operational`**: Additive — an extra run per built edge-handling model (incl. Truth), implemented as a separate pass (`execute_operational_runs`) after the main loop because it needs the Truth investment. Each run copies the edge model, fixes `vGenInvest[g] = 1 if truth_invest[g] > 0.5 else 0` (default-missing → 0, unlike regret's 1) and re-solves. Files `MK-{case}-{edge}-operational.sqlite`, `run_type="operational"`; `--operational` itself is not a run parameter. Truth investment must be *optimal*: the in-memory Truth only if it reached `optimal`, else `_find_optimal_truth_file` (exact file, then `work_limit` siblings, `optimal` only); if neither exists all operational runs are skipped with an error. Under `--skip-truth` a `("Truth ", None)` entry is prepended and the full-hourly Truth is rebuilt **lazily** (only if not no-overwrite-skipped) via `_build_full_hourly_truth_lego(cs, thermal_generator_relaxed)`, which is why `cs` and `thermal_generator_relaxed` are plumbed into `execute_case_study`/`execute_operational_runs`. **`run_type` is in `_SIBLING_COMPARE_KEYS`** so operational and main files are distinct siblings (old main files lack the column → `'None'` matches `None`).

**`--operational-regret`** (requires `--operational`, validated in `main()`): an extra block inside the operational loop — the one place where the Truth investment and the operational `vCommit` are both available. Commitment source: the in-memory operational solve (if it has a solution), else the exact `-operational.sqlite`, else the operational sibling-skip file (soft-fixed, so a work-limited sibling is fine). File values are loaded into a **copy** of the edge model (`lego.copy().model`), not the edge model itself — the edge model's `vCommit` must keep its main-run values for the later original-reference runs. The full-hourly Truth base is resolved once (`truth_base`, built on demand under `--skip-truth`) and copied per edge. Like all regret variants, output files are not appended to `sqlite_files`/`sqlite_labels`; `operational_regret` is not a run parameter (the suffix/`run_type` distinguishes it; `-operational-regret.sqlite` ends in `-regret.sqlite`, so the sibling glob excludes it).

**`--original-reference` flow**: `main()` passes the preprocessed folder *before* `{N} clusters/` as `original_folder` (only for `cluster > 1`); `execute_case_studies` loads it only with `--invest-regret`/`--calculate-regret` and without `--shift-tm`/`--perturb-tm`. `execute_original_reference_runs` runs *after* `execute_case_study`: it first resolves all decisions (`_edge_main_decisions`), stores only `lego.cs` per job, then **deletes `lego_models["Truth "]`** and `gc.collect()`s before building the original model lazily — both are full-year models and must not be in memory together. Truth therefore only gets `-original-invest-regret`. Its transition-matrix metrics use `tm_cs=cs` (the RP case study), also for Truth. Output suffix `-original-{invest-regret|regret}.sqlite` still ends in `-regret.sqlite` (sibling glob excludes it); the files are told apart by `run_parameters.reference = 'original'` (in `_SIBLING_COMPARE_KEYS` and the `EvaluateMarkov.py` keys). `--original-reference-only` (`execute_original_truth`) writes `MK-{data identifier of the base folder}-TruthOriginal.sqlite` with `edge_handling='TruthOriginal'`, `reference='original'`, `clusters=None` and `min_time_cap`.

**`--prepare-only` / list-valued `--clusters`**: `--clusters` is parsed as a string (`'3,5,7'` → list; a single value still combines with `--cluster-steps`). `--prepare-only` runs the full preprocessing chain and `continue`s before `execute_case_studies`. Needed on clusters because the folder creation is not safe against concurrent jobs using `--reuse-inputfiles`.

**`--no-overwrite` check** (main and operational runs, `_no_overwrite_check`):
1. **Exact file exists**: skip only if its `termination_condition` is `'optimal'`; anything else (`'WorkLimit reached'`, `'infeasible'`, unreadable) → re-run and overwrite.
2. **Exact file absent**: `_find_sibling_runs()` finds files in the same directory sharing all `_SIBLING_COMPARE_KEYS` (everything except `work_limit` and the resource options). `_should_skip_smart()`:
   - Any sibling optimal → skip.
   - Otherwise split into *clean* (`{'WorkLimit reached', 'optimal'}` — budget genuinely consumed) and *not-ok* (killed / OOM / error). All not-ok → re-run.
   - Else the best clean sibling (highest `work_limit`; `None` = unlimited = ∞): current `work_limit` **not strictly higher** → skip, strictly higher → re-run. (Unlimited current vs finite sibling → re-run; finite current vs unlimited clean sibling → skip; equal → skip.)
   - Returns the sibling file on both skip rules; regret runs then take their decisions from it (`_edge_main_decisions`), operational-regret its `vCommit`.
Single output files (all regret variants, TruthOriginal) use `_existing_optimal` only.

## Non-obvious patterns — `--task` and `cluster.py` (usage in README, "Cluster runs")

**`--task`/`--edge` (`execute_task`)**: one solve per process. Every input the all-in-one run keeps in memory comes from a result file of an earlier job: Truth investment from `MK-{id}-Truth.sqlite` (must be optimal, rounded like `--operational`), main decisions via `_main_decisions_from_file` (split out of `_edge_main_decisions`), operational `vCommit` from `...-operational.sqlite`. Missing/non-optimal inputs and a non-optimal own output raise (`_require_optimal_file`), and `main()` re-raises in task mode regardless of `--debug` — `cluster.py` relies on the non-zero exit (Slurm `afterok`). All models of a grid point are built through `_build_edge_lego` (also in the all-in-one path), so separate jobs build identical models (`shift_transition_matrix`/`perturb_transition_matrix` are seeded). Full-year models are solved in place (`_solve_fixed_decisions(copy_base=False)`) — a deepcopy would double the peak memory. `--no-overwrite` in task mode checks only the exact output file (no sibling scan: with thousands of files in one folder the scan is slow, and `cluster.py` never varies `work_limit`). The TM plot is written only by the `main/Markov` task (parallel jobs would write the same PNG). `Truth-operational` is a real solve, not a duplicate of Truth main: it is the reference for the operational work units, vShutdown deviation and operational-regret in `EvaluateMarkov.py`.

**`cluster.py`** + **`pool.py`** (stdlib only, run on the login node / any node without the conda env):
- **Arrays and dependencies**: one job array per `(task, edge, dataset)` group. Within a dataset every grid point has the same array index in all groups, so dependencies are `aftercorr` (task i waits for task i of the parent); `group_dependency` falls back to `afterok` on the whole parent array when indices differ (prepare). Grid points are indexed longest first (clusters descending, then `grid.tm` order).
- **Job script** (`runs/<name>/task.sbatch`, shared by `restart`): picks its line from `commands/<group>.tsv` (`index	key	command`) by `$TASK_INDEX` (restarts) or `$SLURM_ARRAY_TASK_ID`, substitutes `@THREADS@` and `@NODEDIR@`, runs a background disk monitor (node-file peak + free disk every 60 s into `$NODE_DIR.usage`, printed by the EXIT trap; warning below `[slurm] disk_min_free_gb`), exports `SRUN_CPUS_PER_TASK` (`srun` does not inherit `--cpus-per-task` since Slurm 22.05) and splits the command on whitespace — `build_plan` rejects arguments with whitespace or quotes. A running run keeps its own `task.sbatch` (restart reuses it), so template changes only affect new submissions.
- **State**: `state.json` keeps every attempt (job id `A_i` or `J`, log, resources); status = `sacct` (finished, incl. step `MaxRSS`) + `squeue -r` (queued/running; `DependencyNeverSatisfied` → blocked). Restart also resubmits unfinished descendants and re-queues `evaluate` with `afterany` on all still-active jobs (cancelled/failed jobs count as ended for `afterany`).
- **Job names** (codes in README) are stored per task as `jobname`; `group` stays the file/state key (`restart` falls back to it for old state files). `build_plan` raises if two arrays share the first 8 characters (all `squeue` shows) — a new task or edge needs a `TASK_CODES`/`EDGE_CODES` entry.
- **Priority** is `sbatch --nice` = task `rank` × `nice_step` (`nice()`; `[slurm] nice_step`, default `DEFAULT_NICE_STEP` = 100, stored in `state["nice_step"]` for `restart`; old state files → default). `rank` = dataset index in `grid.datasets` (evaluate: 0), + number of datasets for **`low_priority` TM variants** (`grid.tm` inline table, `_tm_entry`), which get their own groups (`...-low`, own index sequence from 1; their deps stay within the grid point) because one array has one nice, and a lower-case dataset code in the job name. Users cannot set a negative nice, so the order costs the later ranks the same against other users — keep the step small. `scontrol top` was dropped: it shifts nice zero-sum among the user's own jobs, so passing all jobs in one call gave ±1–3 nice in the wrong order (pilot, Oct 2026). `prioritize` re-applies nice to queued jobs via `scontrol update JobId=<ids> Nice=N` (array id covers its pending tasks).
- **`resource_class(key)`** is the single source of the task → `[resources.*]` class rule (used by `build_plan` and `resources`). `resources` uses `sacct` step `MaxRSS` (peak) and `Elapsed` of `done` tasks only; OOM/TIMEOUT tasks are reported separately because their peak is capped by the request.
- **`node_file_start`** is absolute (GB) per dataset (`_node_file_start`), written literally into the commands — the old `node_file_start_fraction` (× the job's memory) made NodefileStart differ between classes, pilot/full run and `restart --mem`; `build_plan` rejects it with a hint. NodefileStart limits only the B&B tree, so `submit` merely warns when it is ≥ a job's memory.
- **`local`** = a `pool.Worker` on a throw-away pool (temp dir; logs to `--log-dir`): `max_tasks = --jobs`, `thread_cap = CPU count / jobs`, `mem_packing=False` (the TOML memory is sized for Slurm, `-j` is the concurrency), `idle_s=0`. Same code path as `worker`.
- **Mail** is optional: `[slurm] mail_user` or `$MK_MAIL_USER` (versioned configs deliberately have none, to keep the address off GitHub). Without an address, `task.sbatch` has no `--mail-*` lines and the evaluation job no `--mail-type`; `state["mail"]` records this for `restart` (old state files → mail on).

**MUSICA `setup` does not load the Gurobi module**, it only exports `GRB_LICENSE_FILE` (token server) and uses the conda env's `gurobipy`. The `Gurobi/13.0.1-GCCcore-14.3.0` module prepends a Python 3.13 `gurobipy` to `PYTHONPATH`, which shadows the env's Python 3.12 one (`No module named 'gurobipy._batch'`), and it is a user install in the EESSI 2023.06 tree, unknown on login nodes (default EESSI/2025.06; compute nodes default to 2023.06).

## Non-obvious patterns — task pool (`pool.py`, `cluster.py worker`; usage in README, "Task pool")

- **`pool.py` is independent of `cluster.py`**: it gets ready-made specs (`pool_specs`: argv with `python` → `sys.executable`, deps, cpus, prior mem/time from `[resources.*]`, rank) and an `estimate_levels(key)` function; `cluster.py` imports it (`sys.path` insert of its own folder). Keep it stdlib only.
- **Store** (`runs/<name>/pool/`): a task's state is derived from its *highest* attempt — `claims/<task>.<n>` (created with `O_EXCL`, the only mutual exclusion; content = worker id), `results/<task>.<n>.json` (immutable, cached after the first read), `resets/<task>.<n>` (`restart --failed`). A claim without result is running while its worker's heartbeat (`workers/<id>.json`, every 30 s) is younger than `STALE_S` (600 s) and not `exited`; otherwise attempt n+1 may be claimed. Never delete or rewrite claims/results: the attempt numbering is what prevents double runs. No SQLite on the shared filesystem (unreliable locking). `_write_json_atomic` retries `os.replace` (Windows refuses it while another process reads the target).
- **Estimator**: max measurement per level × safety; levels from `estimate_levels` (task → `dataset/task/edge/c<N>` → `dataset/task/edge` → `dataset/class:<cls>`; prepare / truth-original: task → `dataset/<kind>`). Runtime skips the `class:` level (`time_level`): one slow task would otherwise make a whole class "too long" for a job's remaining walltime. Lower bounds: evicted / `oom` → `max(peak, limit)` × 1.25, interrupted / `timeout` → `max(elapsed, limit)` × 1.25. `noop` records (log contains `pool.NOOP_MARKER`, printed by `Markov.py` `_print_noop_marker` when the output existed / all prepare folders were reused) are ignored — keep the marker text in sync. Seeds: `seed_records` reads `runs/<run>/measurements.json` (`resources --save`, Slurm runs) and other runs' pool results.
- **Worker admission** (`admit`): ready = new/retry, not running here, all *selected* deps done (deps outside the specs count as satisfied, like `local`). Order (`Worker.priority`): strict = rank, critical path (sum of runtime estimates down the longest child chain), memory; with `rank_offset_s` (`[pool] rank_offset_hours`) = `low` flag first (low_priority TMs stay last), then critical path − `dataset_rank` × offset, then memory (`dataset_rank` / `low` come from `build_plan`; `rank` = dataset_rank + n_datasets for low). Fits = cores and `Σ max(est, 1.1 × RSS)` + est ≤ `mem_fraction × mem`; a task larger than the machine runs alone. Walltime check only for measured runtimes (priors never block). Head-of-line reservation: after `reserve_after_s` the loop stops at the blocked top task instead of backfilling. **Low-priority tasks** (`spec['low']`, sorted last in both modes) are pure backfill: the admission loop stops at the first low task once a ready normal task did not fit (`waiting_normal`). Started tasks are deliberately never stopped to make room (user decision: a started run continues); only `guard_memory` (newest *low* task first, then the newest overall) and the walltime stop tasks. The claim happens right before `start`, after the fit check.
- **Guards**: memory — evict the newest active task when system `MemAvailable` < 4 % of total or the tasks' RSS > 97 % of `--mem`, never the only one, at most every `evict_grace_s`; TERM, KILL after 30 s (process group on POSIX: `start_new_session`). Walltime — stop all tasks `interrupt_margin_s` before `end_time` (`_slurm_end_time` via `squeue %e`). Disk — no new tasks while the node-file disk is below `disk_min_free_mb`. RSS: Linux `/proc/<pid>/status` VmRSS/VmHWM (peak = VmHWM), Windows `GetProcessMemoryInfo`; only the direct child (Markov.py runs Gurobi in-process).
- **Exit**: a worker never exits while its own tasks run; with nothing ready it waits `idle_s`, and exits at once only when no task remains (all done / failed / blocked by a failure). No runtime prediction is involved (MIP runtimes are not predictable enough).
- **Chaining** (`submit-workers`, `WORKER_SBATCH_TEMPLATE` in `runs/<name>/pool/worker.sbatch`): the worker gets `--chain-script` and calls `Worker.maybe_chain` each poll — once, `chain_after_s` after its start, only if tasks remain, retried every `chain_retry_s` on failure. The submission (`_sbatch_from_job`) strips `SLURM_*`/`SBATCH_*`/`SRUN_*` from the environment, otherwise the running job's settings leak into the successor. Every submitted job is recorded in `jobs/<id>.json` (`status` shows them via `squeue`, `cancel` scancels them). `evaluate` is an `after_all` spec: ready once all other selected tasks are done / failed / blocked (pool equivalent of `afterany`). `work_estimate` = Σ est. mem × time / (mem_fraction × node mem) vs Σ cpus × time / cores, bounded by the critical path; a dry run estimates from a temporary empty store so it creates no pool.
- **Tests** (`research/MK/tests`, pytest, ~1 min): `conftest.py` writes a fake task script (sleep, allocate + touch memory so it shows in the RSS, exit code, optional `MK-NOOP`) and the `mk` fixture monkeypatches `cluster.RUNS_DIR`, `cluster.build_plan` and `cluster._load_config` with fake plans; workers run in-process with short `poll_s`/`idle_s`. `test_cluster_cli.py` uses the real `experiments/experiment.toml` (keep it valid). Several worker tests are timing-based (seconds); a suspended laptop makes them fail spuriously. When changing scheduling behaviour, update/extend these tests.
- **Pool mode of `status` / `restart` / `resources` / `cancel` / `stop`**: `load_pool` detects `runs/<name>/pool/meta.json` (written by the first worker; holds the config path, falling back to `experiments/<run name>.toml` if that path does not exist on this machine) without a `state.json`; `worker` refuses a run name that has a Slurm `state.json`. `cancel` only knows Slurm worker jobs; hand-started workers are stopped with `stop`.
- **Stop requests** (`stop`, `Store.request_stop`): `stop/<target>.json` with target `all` / host name / worker id (lower-cased; matched case-insensitively). A request applies only to workers whose `started_ts` is older than its `time`, so files are never cleaned up and chained successors / later workers are unaffected. `Worker.check_stop` (each full poll): drain = no `admit`, no chaining, exit when nothing runs; `now` = also `stop(..., INTERRUPTED)` the running tasks. Heartbeat field `stopping` → `status` shows "stopping".
- **Dead workers on the same host** (`Store.mark_dead_workers`, at worker start): heartbeats with the own host name whose `pid` no longer exists (`pid_alive`: Windows `OpenProcess` + `STILL_ACTIVE`, access denied = alive; POSIX `kill 0`) are marked `exited`, so their claims are retried at once instead of after `STALE_S`. A reused pid only falls back to the timeout.
- **Windows servers** (usage in README "Windows servers"; a separate site, results never mixed with MUSICA's): one repo clone on the network share is the shared pool / data / result location (`Markov.py` writes `MK-*.sqlite` into the cwd = repo root); workers are started by hand per server, all control (`status`/`stop`/`restart`) goes through the shared pool files. `worker --detach` (`_detach_worker`) validates the config first, then re-runs the same argv (+ `--log`) as a `DETACHED_PROCESS` (tries `CREATE_BREAKAWAY_FROM_JOB` first, so a terminal's job object does not take it down; POSIX: `start_new_session`) and returns. `--log` tees the worker output via `_Tee` into `pool/worker-logs/` (the console may be absent - `_Tee` drops it on the first error). In `pool.py`: tasks go into a kill-on-close **job object** (`_kill_on_close_job`; TerminateProcess of the worker would otherwise orphan a solve that keeps writing the file another worker retries), logged tasks get `CREATE_NO_WINDOW` and `stdin=DEVNULL`. Windows `terminate` is immediate (no grace). `worker` defaults `--cores` to `pool.physical_cores()` on Windows (`GetLogicalProcessorInformationEx`; `os.cpu_count` counts hyperthreads). **`admit` never starts a task with `cpus` > the worker's cores** (logged once per task via `too_large`, left to other workers) - except with `thread_cap` (`local`), where the cap is the user's choice. Nor, with memory packing on, a task whose current estimate exceeds `mem_mb` (whole RAM) while it has **no attempt yet** (`snap[key][1] == 0`; logged once via `too_big`): an eviction raises the estimate as a scaled-up lower bound, which may exceed the RAM although the task fits alone - its retry must still run alone (`alone` covers estimates between the packing share and the RAM). The heartbeat staleness compares the writer's `time.time()` with the reader's: servers' clocks must be synced (domain members are). SMB directory caching delays new claims/results in listings by seconds - harmless, the `O_EXCL` claim is decided by the server. Their config is `experiments/experiment-win.toml` (own `name` = own pool): keep `[grid]` and `[markov] args` in sync with `experiment.toml`. One hardware type per pool, as runtimes are compared within a dataset. `cpus` must stay ≤ the servers' cores and every task meant to run there must have `mem` below their RAM - also `evaluate`, otherwise no worker ever starts it; TX-123BT full / truth-original are deliberately capped just below the RAM (the user wants them tried, not skipped). Keep server specifications (models, counts, RAM) out of the docs and config comments.

## Non-obvious patterns — per-run analysis (section in `Markov.py`)

`write_results` calls `analyze_and_write` after every sqlite write (and under `--no-sqlite`, print-only), so every run kind gets `mk_metrics`/`mk_nonbinarity`/`mk_nonbinary_values`/`mk_feasibility`/`mk_feasibility_violations`. It never raises (each analysis wrapped, failures are warnings) and writes via `closing(sqlite3.connect(...))` + explicit `commit()`. **`tm_cs`**: the transition-matrix columns (`num_rps`, `num_k_per_rp`, `tm_entries`, `tm_nonzero`) describe `tm_cs`; regret-style runs re-solve a 1-RP full-hourly model, so `_solve_fixed_decisions` passes the edge handling's `lego.cs` (original-reference runs: the RP `cs`) — model-size columns still describe the solved model. Gurobi size/runtime/memory come from `lego.solver_attributes` (Gurobi path only; `MaxMemUsed` needs Gurobi ≥ 12). `process_peak_rss_gb` is the process-lifetime high-water mark — use `solver_max_mem_gb` for per-solve memory. The chronology comes from the model's own `cs.dPower_Hindex` in row order; a "day" starts wherever `k == model.k.first()`, so full-hourly models have one day and no transitions (`nb_transition_instances = 0`, `feas_instances = 0`; their residual checks act as a sanity check of the checker). Only *active* thermal units (`pExisUnits + vGenInvest > 0.5`) are counted. The fractional tolerance (`1e-4`) must stay above Gurobi's `IntFeasTol` (1e-5). Feasibility residuals are in model power units; energies in `mk_metrics` are converted to MWh by dividing by `cs.power_scaling_factor`.

## Non-obvious patterns — `EvaluateMarkov.py`

**One loader for all subcommands**: `load_entries` loads every `MK-*.sqlite` (with `--recursive` also subfolders) in a `ProcessPoolExecutor` — `_load_file` must stay module-level (pickled via `functools.partial`), and matplotlib is imported lazily inside the plot functions so spawned workers stay light. Each file becomes one flat entry dict: kind, `base_file`, parsed run parameters + solver statistics (`_load_metadata_from_conn`; filename fallback for files without `run_parameters`), `Objective` (`None` if missing — there is no `-1` sentinel any more), weighted `vStartup`/`vShutdown` sums (SQL aggregation against temp weight tables, never transferring the big tables). `full=True` (tables) adds `vGenP`/`vCommit`/`vPNS`/`vEPS` and the investment results; `analysis=True` (summary) merges the first row of `mk_metrics`/`mk_nonbinarity`/`mk_feasibility` via `setdefault` (run parameters / solver statistics win, e.g. `work_units`) and returns `mk_nonbinary_values`. A weighted sum is `None` if its table is missing.

**Run kinds**: `classify_file` routes by suffix via `_KIND_SUFFIXES` — order matters, `-operational-regret`, `-original-*-regret` and `-invest-regret` all end in `-regret.sqlite` and must be tested before it. It also returns the **base file** (the run whose decisions a regret run evaluates: main file, or the operational file for operational-regret). `TruthOriginal` is a `main` entry with `edge_handling='TruthOriginal'`, `reference='original'`, `clusters=None`.

**Regret is computed once** (`attach_regret`, before any filtering): regret/invest-regret reference the Truth main run with the same `(tm_key, subcase_key)`, operational-regret the Truth-operational run, `reference='original'` runs `TruthOriginal` via `_original_key` (`_base_directory` = `case_study_directory` without the trailing `{N} clusters` + all other `SUB_CASE_KEYS` except `clusters`). Only optimal references unless `--include-nonoptimal`; reference `0`/missing → `regret`/`regret_pct` `None`.

**Selection**: `tables` shows all runs (only `--nrOfClusters`/`--tm` filter). `plots`/`summary` use `select_entries`: optimal main/operational runs passing the filters, plus optimal regret runs whose `base_file` was selected (so a regret value is only used when the run whose decisions it evaluates is itself usable). `--nrOfClusters` drops entries without `clusters` (incl. `TruthOriginal`) — harmless for regret because `attach_regret` runs before filtering. `markov_runs.csv` contains all entries.

**Grouping keys**: `SUB_CASE_KEYS` (all run parameters except `shift_tm`/`perturb_tm`, `work_limit` and the resource options) define a sub-case — the unit the plots' boxes aggregate over and the regret pairing key (together with `tm_key`). `GROUP_KEYS` (`SUB_CASE_KEYS` + `shift_tm`/`perturb_tm` + `reference`) group the `tables` output; `reference` keeps the original-reference runs in their own group. **A new run parameter that should split comparison groups must be added to `SUB_CASE_KEYS`** (and parsed in `_load_metadata_from_conn`'s `converters`). When implementing a new run parameter, proactively ask the user whether and how it should be added to `EvaluateMarkov.py` before closing the task. Note `shift` (time-series shift) is a sub-case key, distinct from the subplot axis `shift_tm`. `shift_tm` is stored as **str**, `perturb_tm` as float — `_tm_value` normalizes both (used by `--tm` matching, sorting and labels).

**`tables`**: per group, the main table, then one table per further kind (`RUN_KINDS` order). `%` columns reference the Truth row; regret tables have no Truth row, so `print_comparison_table` falls back to Markov (flagged yellow, "Differences compared to Markov result"). Investment tables: `vGenInvest` and `vCapInvest` (= `vGenInvest * pMaxProd`, skipped if `pMaxProd` is missing), each total + per technology.

**`plots`**: `render_plots` emits each logical plot twice via `emit()` (full + `_noNoEnf` twin with a reduced `edges` list; the boxes are built once). Box builders return `{tm_key: {edge: [values]}}`. Truth-relative builders (`build_runtime_relative_boxes`, `build_deviation_boxes`) sit on `_iter_vs_truth`, which groups `(tm_key → subcase → {edge: entry})` (keeps the last entry on a collision); `build_regret_boxes` reads `regret`/`regret_pct` of the regret entries directly (`reference is None` only — original-reference regret is not plotted). The work-units plots need Gurobi `work_units` (empty under HiGHS). Y-axis modes in `make_boxplot_figure`: `symmetric_y` (signed deviations), `nonneg_y` (magnitudes), `tight_y` (regrets: down only to `min*1.05`), each widened to keep the MIP-gap band in view; log scale only if `--logscale` and all values > 0. **MIP-gap band** (invest-regret only): `invest_regret_gap_band` is called per drawn edge list; it uses the *requested* `mip_gap` run parameter (not `achieved_mip_gap`, which varies per run and would never collapse the relative band to a line) — `mip_gap*100` (relative) or `mip_gap*|invest-regret Objective|` (absolute); `hi-lo < 1e-9` → drawn as a pair of lines. Figures have no suptitle/legend (subplot titles: dataset name from `_dataset_name` for the base TM, `"Transition Matrix\nshifted by N"` otherwise); `_dataset_name` strips trailing preprocessing folders matching `_PREPROCESSING_SUBFOLDER` (any depth, incl. a bare `data`). Figures are closed after saving (`--separateClusters` renders many).

**`plots` results table**: `build_table_records` reuses the plot box builders (so numbers match the figures) and `_aggregate_boxes` → `{(tm_key, edge): mean/median/min/max/n}`. The LEGO objective is already in M EUR, so the absolute invest-regret needs no conversion. Per-metric `n` legitimately differ — the headline `n_runs` is the operational-deviation count; don't assume one shared `n`. Printed with plain `print` (rich would re-wrap the markdown; strict-ASCII console fallback) and saved as `.txt` (UTF-8) + `.csv`; empty cells are ASCII `"n/a"`.

**Chronological comparisons** (`attach_chronology`, after `attach_regret`, `plots`/`summary` unless `--no-chronology`): a second `ProcessPoolExecutor` pass over the RP main/operational files (`_chronology_worker` must stay module-level), reading `hindex` and the variable tables - the only part of the evaluation that transfers large tables, which is why it is a separate pass and not in `_load_file`. `_index_frame` renames index columns positionally (SQLiteWriter names them after the Pyomo sets, `hindex` has `0/1/2`). Chronology = `hindex` sorted by `p`, one RP per `k.nunique()` rows. `tm_structure` counts transitions circularly like `CaseStudy.get_rpTransitionMatrices`, so `tm_off_diag_mass` matches the model's TM; Truth/regret entries get it copied from their `(tm_key, subcase_key)` group (they are single-RP models). `storage_boundary_check` recovers the start level of each RP from the `eStIntraRes` balance (keep in sync with `storage.py`), so the same formula works for all edge handlings. Dispatch/storage deviation only for operational runs (same fleet as Truth-operational); main runs have different fleets. `--plots` now also loads the analysis tables (`analysis=do_summary or do_plots`) - the operating-cost/curtailment/load-shedding plots need `mk_metrics`. Analysis values come back as NaN from SQLite: use `_num()` (also inside `_iter_vs_truth`). `build_regret_boxes(reference='original')` draws the `-original-*` runs; their plots include a Truth box (clustering error). The results table's fidelity section (`FIDELITY_COLUMNS` / `build_fidelity_boxes`) has a Truth row for `orig_invest_regret` only; the first two tables skip Truth rows.

**`summary`**: `run_kind` = kind + `'@original'` for original-reference runs. The non-binarity histogram weights each `(file, rp, g)` window by `transitions_into_rp` and normalizes by `nb_transition_instances`, so a panel's bars sum to the share of fractional transitions.
